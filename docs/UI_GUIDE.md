# UI 디자인 가이드

## 1. 문서 목적과 범위

이 문서는 Trance Whale MVP의 화면 구성과 사용자 경험 기준을 정의한다. 제품 요구사항은 `docs/PRD.md`, 시스템 경계와 저장 정책은 `docs/ARCHITECTURE.md`를 우선한다.

- 기준 구현: `src/components/home-settings-flow.tsx`, `src/components/reader/reader-view.tsx`
- 기준 스타일: `src/app/globals.css`
- 대상 화면: EPUB 선택, 웹 페이지 URL 보조 입력, 이어 읽기, 리더, 목차, 읽기 및 번역 설정
- MVP는 EPUB 하나를 선택해 읽는 흐름을 우선한다. 선택한 EPUB은 기기에 저장되지만, 내 서재·기기 간 동기화·책별 설정 UI는 제공하지 않는다.
- 화면은 실제 수집, 번역, 검증과 영구 저장 세션 상태를 렌더링한다.

## 2. 디자인 원칙

1. **독서가 중심이다.** 장식보다 본문 가독성, 번역 진행 상태와 장 탐색을 우선한다.
2. **조용한 도구처럼 보인다.** 마케팅용 AI 서비스보다 오래 머물 수 있는 전자책 리더에 가깝게 구성한다.
3. **행동의 결과를 먼저 설명한다.** 저장, 다음 장 적용, 현재 장 재번역을 서로 다른 행동으로 명확히 구분한다.
4. **모바일 한 손 사용을 기본으로 한다.** 360px 화면에서 가로 스크롤 없이 주요 탐색과 설정에 접근할 수 있어야 한다.
5. **개인정보 경계를 화면에서도 드러낸다.** EPUB 파일과 API Key가 기기에만 저장되고 앱 서버로 전달되지 않는다는 점을 입력 영역 가까이 안내한다.
6. **상태를 숨기지 않는다.** 번역 진행, 저장 여부, 현재 읽는 장과 비활성 동작을 텍스트와 형태로 함께 표현한다.

## 3. 시각 방향

밝은 종이색 바탕, 짙은 청록색 탐색 영역과 절제된 황토색 강조를 사용한다. 리더 본문은 따뜻한 흰색 표면 위에 짙은 녹회색으로 표시하여 장시간 독서 시 대비가 지나치게 날카롭지 않도록 한다.

### 3.1 색상 토큰

| 토큰 | 값 | 용도 |
|---|---:|---|
| `--ink` | `#172824` | 제목, 본문, 핵심 정보 |
| `--muted` | `#687873` | 설명, 부가 정보 |
| `--paper` | `#f6f3eb` | 전체 페이지 배경 |
| `--surface` | `#fffdf8` | 리더 본문과 주요 표면 |
| `--line` | `#deddd5` | 구분선, 입력 테두리 |
| `--teal` | `#176b62` | 기본 액션, 진행 상태, 선택 상태 |
| `--teal-dark` | `#0f514b` | 기본 액션 hover |
| `--teal-pale` | `#e6f0ec` | 선택 배경, 정보 안내 |
| `--amber` | `#b06d29` | 장 번호, 미저장 상태, 보조 강조 |
| 탐색 배경 | `#143e3a` | 데스크톱 사이드 레일, 모바일 독서 도구막대 |
| 브랜드 포인트 | `#f4be68` | 로고, 모바일 다음 장 강조 |

### 3.2 시맨틱 사용

- 성공 및 저장 완료: 청록색 + 체크 아이콘 + 상태 문구
- 진행 중: 청록색 진행 막대 + 완료 문단 수 + 백분율
- 주의 및 미저장: 황토색 점 + `저장되지 않은 변경` 문구
- 비활성: 회색 배경과 텍스트 + `disabled` 속성 + 비활성 사유
- 오류: 구현 시 별도 적색 토큰을 정의하되 원본 예외나 외부 응답 본문을 노출하지 않는다.
- 상태는 색상만으로 구분하지 않는다.

## 4. 타이포그래피

별도 웹 폰트 다운로드를 전제로 하지 않고 시스템 폴백을 사용한다.

| 용도 | 글꼴 | 기준 스타일 |
|---|---|---|
| 앱 UI | `Arial`, `Noto Sans KR`, sans-serif | 명확하고 작은 크기에서도 식별 가능한 산세리프 |
| 본문·장 제목 | `Georgia`, `Noto Serif KR`, serif | 독서 중심의 세리프 |
| 홈 제목 | 세리프 | `46–72px`, 행간 `1.08`, 가운데 정렬 |
| 모바일 홈 제목 | 세리프 | `42px`, 행간 `1.12`, 왼쪽 정렬 |
| 장 제목 | 세리프 | 데스크톱 `34px`, 모바일 `28px` |
| 본문 | 세리프 | 기본 `19px`, 사용자가 `16–24px` 조정 |
| 본문 행간 | 세리프 | 기본 `2.08`, 모바일 `2` |
| UI 본문 | 산세리프 | 주로 `10–14px`, 역할에 따라 굵기 차등 |

본문은 모바일에서도 최소 16px을 보장한다. 긴 장 제목은 한 줄 말줄임을 사용하되 전체 제목을 확인할 수 있는 목차를 제공한다.

## 5. 전체 레이아웃

### 5.1 데스크톱

- 좌측에 너비 `84px`의 고정 사이드 레일을 둔다.
- 홈, 목차, 설정을 아이콘과 텍스트로 함께 표시한다.
- 홈 EPUB 가져오기 영역은 최대 `740px`이다.
- 리더 본문 열은 최대 `760px`이다.
- 설정과 목차는 화면 오른쪽에서 열리는 최대 `470px` 시트로 제공한다.

### 5.2 모바일

- 기준 최소 너비는 `360px`이다.
- 사이드 레일 대신 높이 `62px`의 상단 헤더를 사용한다.
- 홈 제목과 설명은 왼쪽 정렬한다.
- EPUB 선택 버튼과 가져오기 안내를 먼저 배치하고, URL 입력과 제출 버튼은 접을 수 있는 보조 영역에서 세로로 쌓는다.
- 설정과 목차는 화면 하단에서 시작하는 전체 너비 시트로 표시한다.
- 리더 하단에 이전 장, 목차, 홈, 설정, 다음 장을 포함한 고정 도구막대를 표시한다. 설정 아이콘은 기존 읽기 및 번역 설정 시트를 연다.
- 아래로 스크롤하면 도구막대를 숨기고 위로 스크롤하면 다시 표시한다. 8px 미만의 흔들림은 무시하며, 본문 최상단·장 전환·설정 또는 목차 시트 사용 중에는 표시한다.
- 숨겨진 도구막대는 터치와 키보드 탐색에서 제외한다. 시트를 닫으면 열었던 버튼으로 포커스를 돌려주며, 동작 줄이기 설정에서는 슬라이드 전환을 생략한다.
- 고정 도구막대와 시트는 `env(safe-area-inset-bottom)`을 고려한다.
- 고정 도구막대가 본문이나 푸터를 가리지 않도록 하단 여백을 확보한다.

## 6. 핵심 화면과 흐름

### 6.1 홈과 EPUB 선택

1. 제품의 역할과 사용자가 콘텐츠 이용 권한을 보유해야 한다는 점을 한 문장으로 설명한다.
2. 기본 CTA로 `.epub` 파일 선택 버튼을 제공한다. 파일을 앱 서버에 업로드하지 않고 이 기기에만 저장한다는 점을 가까이 안내한다.
3. URL 입력은 `웹 페이지 가져오기`라는 접을 수 있는 보조 영역에 둔다. 지원 도메인은 이 영역 안에서 안내한다.
4. 마지막 EPUB 장 또는 웹페이지 읽기 상태가 있으면 입력 영역 아래에 `이어 읽기` 카드를 제공한다.

EPUB 선택 취소, 손상 EPUB, DRM·이미지 기반 EPUB과 저장공간 부족은 서로 다른 안전한 메시지로 표시한다. 보조 URL 제출 버튼은 `번역해서 읽기`처럼 결과가 분명한 동사를 사용하며, 잘못된 URL·미지원 도메인·접근 실패도 구분한다.

### 6.2 리더

리더는 다음 순서를 유지한다.

1. 작품명과 장 번호
2. 목차와 읽기 설정 접근
3. 장 제목과 원문 제목
4. 번역 진행 상태
5. 본문 보기 모드
6. 완료된 번역 문단과 로딩 자리 표시자
7. 이전 장, 목차, 다음 장

번역 중에도 완료된 문단부터 표시한다. 진행 상태에는 상태명, 완료 문단 수, 진행 막대, 백분율과 취소 버튼을 포함한다.

### 6.3 본문 보기 모드

- `번역문`: 기본 모드이며 한국어 번역만 표시한다.
- `원문`: 원문만 표시한다.
- `함께 보기`: 한 문단 안에서 원문을 먼저, 번역문을 다음에 표시한다.

선택된 모드는 배경, 글자 굵기와 텍스트 상태로 구분한다. 원문은 번역문보다 작고 옅게 표시하되 읽을 수 있는 대비를 유지한다.

### 6.4 장 이동

- 본문 끝에는 장 제목을 포함한 큰 이전/다음 이동 영역을 둔다.
- 모바일 독서 중에는 고정 도구막대로 이전 장과 다음 장에 즉시 접근할 수 있게 한다.
- EPUB을 가져온 뒤에는 첫 장을 열고, 새 장을 열면 새 본문의 시작 위치로 이동한다.
- 이미 읽던 장으로 돌아온 경우에는 저장된 스크롤 위치 복원을 우선한다.
- 이전/다음 버튼은 원본 사이트로 직접 이동하지 않고 앱 내부 리더 상태를 갱신한다.
- 이전 또는 다음 장이 없으면 해당 버튼을 비활성화하고 이유를 접근성 이름으로 제공한다.

### 6.5 목차

- 오른쪽 또는 하단 시트로 열어 현재 독서 맥락을 유지한다.
- 작품명, 전체 장 수, 검색과 정렬을 제공한다.
- 현재 읽는 장을 배경, 상태 문구와 화살표로 강조한다.
- 장 번호와 원문 제목을 검색할 수 있게 한다.
- 수백 개 이상의 장 목록은 실제 구현에서 가상화한다.

MVP는 단일 작품 흐름을 사용한다. 새 EPUB을 선택하거나 새 작품 URL을 입력하면 활성 작품과 목차가 교체되며, 내 서재 UI는 제공하지 않는다.

## 7. 설정과 저장 UX

### 7.1 설정 항목

- 본문 글자 크기
- 사용자 번역 프롬프트
- 번역 모델
- Gemini API Key

### 7.2 번역 설정 저장 순서

사용자 프롬프트, 번역 모델과 API Key는 하나의 저장 흐름으로 취급한다.

```text
값 변경
  → 저장되지 않은 변경 표시
  → 현재 장 다시 번역 비활성화
  → 변경사항 저장
  → 저장됨 · 다음 장부터 적용
  → 필요할 때 현재 장 다시 번역
```

- 패널을 닫아도 현재 세션의 작성 중 값은 유지한다.
- 저장하지 않은 값으로 번역을 시작하지 않는다.
- 저장하면 이후 새로 번역하는 장부터 적용한다.
- 이미 번역된 현재 장은 자동으로 폐기하지 않는다.
- 사용자가 `현재 장 다시 번역`을 명시적으로 선택해야 저장된 설정으로 현재 장을 갱신한다.
- 실제 구현에서는 저장 성공과 실패를 명확히 알리고, 저장 실패 시 작성 중 값을 보존한다.

### 7.3 사용자 프롬프트

- 라벨은 `나만의 번역 지시`를 사용한다.
- 이름 표기, 말투와 문체처럼 추가할 내용의 예시를 제공한다.
- 빈 값도 허용한다.
- 기본 번역 원칙은 사용자 프롬프트와 별도로 항상 적용됨을 알린다.
- 최대 길이와 현재 글자 수를 함께 표시한다.

### 7.4 번역 모델

- `빠른 번역`을 기본이자 추천 항목으로 표시한다.
- `고품질 번역`은 문체와 맥락 우선이라는 상대적 차이를 설명한다.
- 모델 변경은 저장 전까지 적용하지 않는다.
- 유료 전용이라고 단정하거나 무료 할당량을 고정 수치로 보장하지 않는다.

### 7.5 API Key

- 직접 입력하고 수정할 수 있어야 한다.
- 기본 상태는 `password` 필드로 마스킹한다.
- 입력 오른쪽에 텍스트가 포함된 `표시/숨기기` 버튼을 제공한다.
- 설정 시트를 닫거나 다시 열면 숨김 상태로 초기화한다.
- Key 변경도 하단 저장 전까지 적용하지 않는다.
- Key가 앱 서버로 전송되지 않고 브라우저 저장소가 완전한 보안 저장소는 아니라는 사실을 가까이 안내한다.
- API Key를 URL, 오류 메시지, 분석 이벤트, 캐시 키와 테스트 스냅샷에 포함하지 않는다.

## 8. 컴포넌트 기준

### 버튼

- Primary: 청록 배경, 흰색 텍스트, 명확한 동사
- Secondary: 투명 또는 흰색 배경, 중립 테두리
- Destructive: 실제 삭제 기능 구현 시 별도 위험색과 확인 단계 적용
- Disabled: 회색 배경과 텍스트, 포인터 비활성화, 사유 안내
- 모바일 주요 터치 영역은 최소 44px을 목표로 한다.

### 입력 필드

- 흰색 배경과 `--line` 계열 테두리를 사용한다.
- placeholder만으로 라벨을 대체하지 않는다.
- focus 시 청록색 테두리와 낮은 투명도의 focus ring을 사용한다.
- 비밀 입력은 마스킹과 표시/숨기기를 함께 제공한다.

### 상태 표시

- 번역 진행: 정보 박스 + 진행 막대 + 수치
- 저장 완료: 체크 아이콘 + `저장됨` 문구
- 미저장: 황토색 점 + `저장되지 않은 변경` 문구
- 캐시 완료: 체크 아이콘 + `기기에 저장됨` 문구

### 시트와 오버레이

- 데스크톱은 오른쪽 시트, 모바일은 하단 시트다.
- 제목, 맥락 정보와 닫기 버튼을 시트 상단에 고정된 순서로 둔다.
- 바깥 영역 선택과 닫기 버튼으로 닫을 수 있어야 한다.
- 실제 구현에서는 `Escape`, 초기 focus 이동과 닫은 후 focus 복원을 지원한다.

## 9. 애니메이션

허용하는 애니메이션은 기능적 전환에 한정한다.

- 시트 오버레이 fade: 약 `180ms`
- 시트 진입 slide: 약 `240ms`
- 모바일 독서 도구막대 진입: 약 `200ms`
- 번역 대기 자리 표시자 pulse: 약 `1.5s`
- `prefers-reduced-motion: reduce`에서는 애니메이션을 사실상 제거한다.

네온 글로우, 무한 장식 모션과 독서 중 본문을 움직이는 효과는 사용하지 않는다.

## 10. 아이콘

- 인라인 SVG를 사용한다.
- 기본 크기는 `18–20px`, 기본 `stroke-width`는 약 `1.7`이다.
- 아이콘만 있는 버튼에는 반드시 접근성 이름을 제공한다.
- 의미 없는 둥근 아이콘 컨테이너를 반복하지 않는다.
- 같은 방향 이동은 같은 화살표 형태를 사용한다.

## 11. 접근성 체크리스트

- 시맨틱 `main`, `section`, `article`, `nav`, `button`, `label`을 우선한다.
- 키보드만으로 EPUB 선택, 웹 URL 입력, 보기 모드, 목차, 설정과 장 이동을 사용할 수 있어야 한다.
- dialog에는 이름과 modal 상태를 제공한다.
- 번역 진행 상태는 보조 기술이 인식할 수 있게 한다.
- 입력에는 화면에 보이는 라벨 또는 동등한 접근성 이름을 제공한다.
- focus 표시를 제거하지 않는다.
- 선택, 오류, 진행과 비활성 상태를 색상만으로 표현하지 않는다.
- 360px에서 가로 스크롤과 텍스트 겹침이 없어야 한다.

## 12. AI 슬롭 안티패턴 — 하지 마라

| 금지 사항 | 이유 |
|---|---|
| `backdrop-filter: blur()` | 독서 도구보다 유행성 템플릿처럼 보인다. |
| 그라데이션 텍스트 | 본문 중심의 차분한 위계를 해친다. |
| `Powered by AI` 장식 배지 | 사용자 가치나 상태를 설명하지 않는다. |
| 글로우 및 네온 애니메이션 | 장시간 독서를 방해한다. |
| 보라·인디고 중심 AI 팔레트 | 제품의 종이 기반 독서 방향과 맞지 않는다. |
| 모든 요소에 같은 큰 radius | 위계가 사라지고 템플릿처럼 보인다. |
| 흐릿한 배경 구체 장식 | 기능과 무관하며 본문 집중도를 낮춘다. |
| 과도한 카드 중첩 | 정보 관계를 불필요하게 분절한다. |
| AI를 의인화한 진행 문구 | 실제 처리 상태와 다음 행동을 흐린다. |

## 13. 구현 검수 기준

- 360px에서 EPUB 선택부터 리더 탐색까지 가로 스크롤 없이 완료한다.
- 번역문, 원문과 함께 보기 전환 시 문단 대응 관계가 명확하다.
- 완료된 번역 문단은 전체 번역 전에도 읽을 수 있다.
- 목차와 읽기 설정은 독서 위치와 관계없이 접근 가능하다.
- 프롬프트, 모델 또는 API Key 변경 후 저장 전 재번역을 실행할 수 없다.
- API Key는 기본 마스킹되고 표시/숨기기 상태가 정확하다.
- 새 장은 본문 시작에서 열리고, 읽던 장은 저장된 위치를 복원한다.
- 상태는 텍스트, 형태와 색상을 함께 사용한다.
- `test`, `typecheck`, `lint`, `build` 검사를 통과한다.

## 14. UI 회귀 방지

기준 구현에 없는 시각·상호작용 변화는 기능 구현의 부수 효과로 취급하지 않는다. 변경 전후에 아래 보호 대상을 비교하고, 의도한 변화만 남긴다.

- 360px: 홈의 EPUB 선택, 리더 상단과 하단 장 이동, 목차·설정 시트, 번역 모델 선택, API Key 입력·표시/숨기기
- 데스크톱: 사이드 레일의 아이콘과 라벨, 리더 장 이동, 우측 목차·설정 시트
- 모든 크기: 아이콘 버튼의 접근성 이름, 최소 44px 터치 영역, disabled 이유, focus 이동과 시트 닫은 뒤 focus 복원

승인된 디자인을 수정할 때는 `docs/VALIDATION.md`의 개발·통합 회귀 방지 기준에 따라 360px과 데스크톱 결과를 확인한다. 동작을 보존한다는 이유로 아이콘을 텍스트로 교체하거나, 모델 선택·API Key 입력의 위계와 안내를 단순화하지 않는다. 이런 변화가 필요하면 작업 설명과 검수 기준에 의도를 먼저 적는다.
