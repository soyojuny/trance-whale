# Architecture Decision Records

## 철학

Trance Whale MVP는 사용자의 Gemini API Key와 원본 콘텐츠를 서버에 남기지 않는 경계를 우선한다. 검증 가능한 작은 브라우저 로컬 기능을 선택하고, 외부 사이트와 실제 Gemini 품질처럼 결정적 자동화가 불가능한 항목은 수동 검증 기록으로 명확히 분리한다.

---

### ADR-001: 오프라인 리더 복원을 위한 ChapterSource 캐시

**결정**: 검증된 `ChapterSource`를 IndexedDB의 source cache에 canonical URL 기준으로 저장한다. 온라인에서 받은 source는 번역 시작을 지연시키지 않고 저장하며, 오프라인에서는 source cache와 완전한 translation cache가 모두 있을 때만 장을 복원한다.

**이유**: 번역 cache만으로는 제목, 원문 문단, 콘텐츠 해시, 이전/다음/목차 navigation을 재구성할 수 없다. source와 번역을 함께 보관하면 source API나 Gemini API를 호출하지 않고도 이미 읽은 장을 표시할 수 있다. source 응답 런타임 검증을 재사용해 손상된 저장 데이터는 안전한 cache miss로 처리한다.

**트레이드오프**: 원문 구조화 데이터가 브라우저 저장 공간을 추가로 사용하며 IndexedDB 스키마 업그레이드와 저장 실패 처리가 필요하다. 캐시는 공개 source 데이터만 보관하고 API Key, 사용자 프롬프트, 번역 요청은 보관하지 않으며, 저장되지 않은 새 장은 오프라인에서 열 수 없다.

### ADR-002: 부분 번역 실패 시 실패 chunk만 재시도

**결정**: 부분 실패 상태에는 성공한 문단과 실패한 chunk 식별자를 유지하고, 재시도 시 검증된 실패 chunk만 Gemini에 보낸다. 결과는 문단 ID로 기존 성공분과 병합하고, 모든 문단이 정확히 한 번씩 갖춰진 완전한 결과만 translation cache에 저장한다.

**이유**: 이미 성공한 문단을 다시 요청하면 사용자 할당량과 잠재 비용을 낭비하고, 읽고 있던 번역문도 불필요하게 다시 처리한다. ID 기반 병합은 순서와 누락을 검증해 부분 결과를 안전하게 보존하면서 PRD의 선택적 재시도 요구사항을 충족한다.

**트레이드오프**: 세션 상태와 pipeline 입력이 더 복잡해지고, chunk 경계 또는 원문이 달라진 경우 기존 성공 결과를 재사용할 수 없다. 재시도가 다시 실패하면 불완전 결과를 cache에 저장하지 않아 다음 방문에는 다시 번역해야 하지만, 잘못된 완성본을 재사용하는 위험을 피한다.
